# MLB fixture and pitcher context cutover

Install the MLB service and timer alongside the release, then run the service before enabling the timer. A successful empty calendar writes `schedule_status: no_games_scheduled` and a current UTC `observed_at` to `data/mlb_fixture_context/latest.json`. On an HTTP 406, an unprojected MLB schedule can confirm an empty window. If the date-range request also returns 406, the collector checks the official season calendar for the requested dates. If an MLB fixture is scheduled and the detailed endpoint is unavailable, the service reports a source failure and keeps the prior cache's timestamp. An expired cache cannot supply new grades.

The board, maintenance runner, and performance ledger read the cache locally. The separate probable-pitcher request can fail without preventing core fixture collection. A confirmed starter requires official first-inning pitch and starter evidence. The collector stores the observation timestamp in `pitcher_changes.jsonl` when pitcher collection is enabled.

For the approved integrity cutover, write the UTC activation timestamp to `data/mlb_fixture_context/active_from` under the existing production deployment locks. Keep it with the deployment backup. New MLB grades from that boundary require fixture-proven scores, and previously recorded MLB grades remain frozen. The cutover has no qualification or routing settings. An unavailable or stale source leaves new MLB finals unresolved. An official postponed or suspended game stays unresolved, and a rescheduled fixture needs proof for its updated fixture date and start.

Verify the current revision, prior MLB grades, fixture cache and scheduler before release sign-off. Use `RED_FOX_MLB_STATIC_MONEYLINE=auto` in the existing runner environment. The fixture timer and board refresh verify two consecutive populated fixture collections and two distinct fresh MLB moneyline captures with exact fixture and paired-quote matches. Promotion also requires a recent settlement written by the verified MLB score path and checked against the official result. The existing exact fixture matcher requires first-pitch proof for ambiguous doubleheader placeholders. Opening-day activation may wait for the first completed grade from the regular-season feed.

The first activation writes `data/mlb_static_activated_at` once. `data/mlb_fixture_context/static_readiness.json` preserves evidence counters, status, and transition reasons across restarts. A failed readiness check immediately holds new promotions. Two failed board checks suspend the pathway until two fresh successful checks restore readiness. Activation and recovery apply to later market observations. Existing Favorites continue through the ordinary lifecycle. The qualifying price, thresholds, confirmation, and settlement policy are unchanged.

Set `RED_FOX_MLB_STATIC_MONEYLINE=0` or create `data/mlb_fixture_context/disable_static` to override automation. The fixture timer automatically retries pitcher context after publishing the essential fixture cache. Create `data/mlb_fixture_context/disable_pitchers` to stop optional pitcher collection independently. `RED_FOX_MLB_STATIC_RETRACE_LOG` still controls retrace diagnostics separately.

To roll back automation, hold new promotions with the manual switch, revert only the automation commit, and restore the runner environment, pitcher hold, and expected revision from the deployment backup. Keep the fixture timer and integrity cutover active. Preserve the score history, ledger, activation marker and readiness evidence.
