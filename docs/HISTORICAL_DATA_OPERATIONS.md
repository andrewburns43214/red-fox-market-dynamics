# Red Fox historical data operations

The historical pipeline runs independently of market capture, board publication, official qualification, and the Favorite ledger. It never writes to those files. The raw capture archive remains the authoritative record of accepted observations.

## Production paths

- data/snapshots.csv holds the existing hot capture window. The existing runner rotates older rows into data/snapshot_archive when the hot file reaches its threshold. Keep all legacy raw files, including checked source copies outside that directory.
- /var/lib/redfox-history/private/history.sqlite3 stores lossless compressed quote blocks keyed by sport, fixture, market, and UTC date. Point-in-time queries decode only the relevant blocks. Quote blocks retain every indexed timestamp, selected-side price, opener, split, schedule, and evidence field. Exact duplicate quotes index once. Conflicting values at the same market-side timestamp are retained as variants. Fixture identity, decision evidence and research outcomes remain in separate tables.
- /var/lib/redfox-history/private/research holds attributable imports and source manifests. Keep verified results separate from official records. Do not treat an unresolved or unavailable result as a loss.
- /var/lib/redfox-history/public/data/anomaly_event_details serves retired details as gzip through the existing authenticated URL. Nginx checks for a current uncompressed Game Detail first. The retirement job waits until detail files are inactive, compresses and verifies identical bytes, and takes the existing publication lock nonblocking before removing the redundant rendering. If publication is in progress, the job retries the first file during a bounded idle wait. A conflict keeps both copies for review.
- The history observer captures changes from the published board. The historical index also imports the retained decision ledger and compact publication transitions. Expiring rendered source HTML continues to serve diagnostics. Historically missing states are never reconstructed and presented as originally published.

## Scheduled jobs and monitoring

Install the history observer, maintenance, detail and health units in deploy. Enable the detail timer after testing the protected Nginx fallback with both gzip and identity clients. Check journal entries for the four units after rollout. The health job writes a daily /var/lib/redfox-history/private/health.json, rotates across stored SHA-256 checksums, and raises an early warning below 15 GiB available. Existing disk and freshness monitors remain in effect. The maintenance job indexes the hot tape and finalized shards, then reconciles pending results. It independently checks exact fixture identities and leaves ambiguous rows unresolved.

Below the 15 GiB reserve, quote indexing and comparison materialization defer while normal capture, protected Game Detail service and compression continue. The maintenance unit migrates the former per-quote table by fixture with a persisted cursor and verifies every migrated block before retiring the old derived table. SQLite releases those pages only when the compaction can complete above the reserve. Repeated starts resume automatically. Keep the complete compressed capture tape as the reconstruction source. Compare recurring free space, quote payload bytes, fixture counts, and compressed Game Detail growth after initial backfill and during peak seasons. A falling reserve margin first calls for checking transient files, exceptional ingest growth, and the projected annual rate.

Archive intake processes newer finalized gzip shards before legacy backup copies. It has a seven-minute maintenance budget and resumes at the last committed CSV record. The quote blocks, fixture metadata and resume position are committed together. The source manifest gains a SHA-256 record once the complete file has been indexed. A budget deferral is expected during legacy backfill.

## Backup and recovery

Enable redfox-history-backup.timer only after an existing private remote restic repository has been approved and tested. Install restic using the host package manager and store repository credentials in a root-only /etc/redfox-history-backup.env or its referenced credential files. Supply RESTIC_REPOSITORY and RESTIC_PASSWORD_FILE. Keep a recovery copy of the repository credentials outside production and separate from the repository.

The backup wrapper takes the manual SQLite database through SQLite's online backup API and exports private decision/outcome tables using one read transaction. It backs up canonical inputs and irreplaceable records with restic's versioning and chunk deduplication. Preserve closed gzip shards, legacy copies, research imports, qualification records and mappings. Check the repository on a recurring schedule with the wrapper's check command. Establish a retention policy for backup generations with the owner before running any restic forget or prune operation. Preserve permanent historical input data in the retained snapshots.

For a recovery drill restore a tagged backup into an isolated directory or instance. Use `history_store.py --state <new-private-dir> --input <restored-backup-stage> restore-evidence` to recover private evidence. On that isolated state, rebuild the quote index with the restored application's `--root`, `archive` and `hot` commands. Restore the private research directory into that state before indexing its quote files. Check database integrity, and compare a pregame game trajectory and exact entry price against its verified result. Include a non-Favorite and an official or manual Favorite. Verify that archive timestamps precede the result, and that conflicting or unresolved fixtures stay ungraded. Measure the backup age and recovery time. A working same-host copy leaves host-loss recovery unverified.

## Historical Market Comparisons

The maintenance timer builds private checkpoints 72, 48, 36, 24, 16, 10, 6, 4 and 3 hours before the schedule known from the capture, then at 120, 90, 60, 40, 30, 20 and 10 minutes. The most recent valid two-sided quote must be at or before the checkpoint and within 20 minutes of it. An earlier verified actual start censors both later quotes and later checkpoints. UFC requires verified individual-bout timing. Some older observations lack reliable schedules and remain available only as archive evidence.

Query `paired_as_of` for exact trajectories or `history_comparisons.candidates` for historical windows that already have verified outcomes as of the comparison date. Market movement, splits, exact entry odds, prior path, same-side cross-market evidence, and the known publication context are independent of settlement. Research grades require a usable provider identity and price. Conflicts, ambiguous opponent identities and unverified shortened MLB totals stay out of graded samples. Keep the comparison date and checkpoint in any downstream report to prevent look-ahead. The index is private and runs outside live publication or qualification.

Install the public comparison and monitor units from `deploy/` and enable their timers. Install `deploy/redfox-history-comparisons.nginx.conf` as `/etc/nginx/redfox-history-comparisons-enabled.conf` through the existing board locations include. Test Nginx configuration and verify that unauthenticated requests for a comparison return 401 before activating publication.

The comparison worker generates protected JSON in `/var/lib/redfox-history/public/comparisons` on a separate five-minute timer. Overlapping timer ticks do not start a second worker. New board evidence, changed historical windows and newly verified outcomes invalidate the relevant cached payloads. Slow cycles prioritize new freezes and the oldest pregame payloads. During feed delays the worker can reuse the exact verified capture that the board still shows for a game before its start. The popup labels that capture and its observation time.

The manifest points to the exact published payload and advertises each market side only when it has a priced, graded comparison. Versioned payload paths are hard links and remain available for at least 45 minutes after their last publication. Frozen and pregame publications use separate versions. If markets reach the frozen view in separate handoffs, the worker can add an absent market with a verified capture before the earliest recorded start. Existing frozen markets keep their original snapshots and grades. Game Detail distinguishes insufficient samples, unverified results, pending backfill, source coverage gaps and publication delays. To pause new publications and hide comparison buttons, create `/etc/redfox-history-comparisons.disabled` and start `redfox-history-public.service` once. Remove the file and start the service to re-enable.

Within each same-sport cohort, the selected wager supplies the archived price and grade. Its matching score also uses paired peer-market captures from the same fixture and schedule, no more than 20 minutes before the selected quote. Available secondary context contributes 24% of the score and considers splits, movement, juice, reversals and cross-market direction. A directly contradictory spread–moneyline pattern cannot be a closest match when both patterns are known. Broader matches relax that requirement and include closest matches. Missing peer evidence is left unscored. Team-market comparisons use Over for total context. Total comparisons align team evidence by the opening moneyline favorite, with the opening spread favorite as a fallback. Cross-sport comparisons continue to use normalized football or basketball moneyline evidence without comparing raw spreads and totals across leagues.

New comparisons have an immutable, compressed side ledger served as protected JSON. It preserves each graded member, price, result, match reason, and the primary and available peer evidence. The browser loads only the selected side's ledger from the popup. The entire group and overlapping descriptive slices preserve the original group membership. The complete ledger size must reconcile to each headline before publication. Older frozen snapshots keep their recorded examples and original aggregate. Their omitted rows cannot be recovered exactly from a newer index.

The worker retains active ledger files for 90 minutes after their last publication. Frozen snapshots pin the exact ledger bytes by hard link in the private `.frozen-ledgers` subdirectory of the comparison directory. Preserve that directory together with the `comparison_frozen` records and the private prospective database in any backup or restoration of the comparison evidence. The protected route needs both the Nginx static-gzip and gunzip modules. Clients use the same authorized GET route for headers and ledgers. The live market publisher has no ledger dependency.

The prospective study saves a single result per league, fixture and market when an actual publication lands between T−60 and T−40 using a paired capture at or before T−60 and no more than 20 minutes older. It saves the actual observation and publication clocks, outcome knowledge cutoff, entry quote, immutable comparison ledger, and no-vig fair probability for the observed two-way market. A deterministic team side or Over is selected before grades are known. Fixed forecasts use the original cohorts and two descriptive refinements with the same 15-neighbor minimum, 100-neighbor cap and 20-observation shrinkage. Unsupported adjustments pass through the same no-vig baseline. Their effective sample counts stay visible in the private summary. Provider IDs deduplicate resolved fixtures within a market. Closing evidence at or before publication excludes any post-start forecast and contradictory grades remain pending. Quotes and eventual verified results are stored separately from official settlement in `comparison-prospective.sqlite3`. The worker checks a bounded pending batch and refreshes its private summary hourly. Brier metrics compare decisive outcomes on the same queries. Pushes return the flat-unit stake and are excluded from Brier scoring. Any new research recipe needs a separately versioned study before using the prospective holdout.

The private study summary also reports each closest and broader cohort by the sign of its historical ROI at publication. The existing 15-observation research floor separates sparse cohorts. Older receipts use their saved immutable proof. Compare subsequent flat-stake ROI to the expected ROI at the same entry quote under its paired no-vig probability. Compare Brier differences on the same decisive outcomes. Closest and broader groups overlap, and results for different markets on one fixture may be dependent.

The normal maintenance job upgrades old window payloads in place alongside new quotes. It rotates upgrade slots across sports and yields to archive indexing after an eight-minute checkpoint budget. `history_comparisons.py --upgrade-existing` advances the same queue in bounded batches. Older checkpoint rows remain usable while joint context is being rebuilt. The raw archive importer resumes at committed CSV boundaries and records each byte-identical source without indexing it a second time. Recent verified results are also rechecked for corrections using the existing sources and provider identities. A later result revision is available to upcoming comparisons after it is verified. Conflicting independent scores stay ungraded. The frozen pregame payload remains fixed in the private history database and can be served again after its generated JSON expires.

The monitor uses the existing Resend credential and persists its delivery and disk threshold state in the private history directory. It checks storage, historic capture and archive health, outcome reconciliation, comparison generation and off-host backup status. The forecast uses at least 21 daily samples. Off-host backups remain an independent, disabled service until an approved destination exists.
